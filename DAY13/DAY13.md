# DAY 13: 게임 서버 응용, 데이터, 리포트, 패치

## 1. 코인 게임 데이터 흐름

| 상황 | 즉시 처리 담당 | 저장 담당 | 운영 기록 |
| --- | --- | --- | --- |
| Player가 코인에 닿음 | Game Server가 거리·중복 확인 | 게임 종료 또는 저장 시 DB에 Score 기록 | CoinCollected 횟수 |
| Client 접속 실패 | 접속 모듈이 실패 반환 | 저장하지 않음 | 실패 시각·오류 코드 |
| 새 버전 배포 | Patch 서버가 버전 비교 | 파일 목록·버전 정보 관리 | 적용 성공·실패 수 |

## 2. Score 저장 구조

플레이어 점수의 영구 저장 데이터는 다음 세 필드로 구성한다.

| 필드 | 타입 예시 | 설명 |
| --- | --- | --- |
| PlayerId | int | 플레이어 식별값 |
| Score | int | 저장할 플레이어 점수 |
| LastSavedAt | DateTime | 마지막으로 저장된 시각 |

예시:

```text
PlayerId: 101
Score: 15
LastSavedAt: 2026-10-19 12:00:00
